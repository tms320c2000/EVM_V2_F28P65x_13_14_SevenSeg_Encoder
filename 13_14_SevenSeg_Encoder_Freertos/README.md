# 엔코더(eQEP)로 7-세그먼트 00~99 카운터 — TMS320F28P65x FreeRTOS 버전

**요약**
- 개발보드 V2의 **(14) 로터리 엔코더(24P/R)** 를 칩의 **eQEP1** 로 읽어서 **(13) 7-세그먼트 2개** 에 **00~99** 로 표시합니다. 오른쪽으로 돌리면 +1, 왼쪽으로 돌리면 -1, 노브를 누르면 00으로 리셋되고 누르는 동안 점(DP)이 켜집니다.
- [DriverLib 버전](../13_14_SevenSeg_Encoder_Driverlib/)과 같은 GPIO/eQEP 코드를 쓰되, 반복 실행을 **FreeRTOS 태스크 2개**(엔코더 입력, 표시)로 나눴습니다. 힙을 쓰지 않는 정적 할당 구성입니다.
- 배선, 동작 설명, PC 단위 시험, 문제 해결은 DriverLib 버전 README에 자세히 있습니다. **보드에서는 아직 확인하지 않았습니다**(빌드만 확인).

## 1. 하드웨어 배선 (세 버전 공통)

개발보드 **A Side 핀-헤더** 에 점퍼선 13개로 연결합니다.

| 개발보드 핀-헤더 | 신호 | GPIO | A-Side 핀 |
|---|---|---|---|
| (13) A1, B1, C1, D1 | 1번 자리(왼쪽) BCD, A = LSB | GPIO0, 1, 2, 3 | 65, 67, 69, 71번 |
| (13) DP1 | 1번 자리 점 | GPIO4 | 73번 |
| (13) A2, B2, C2, D2 | 2번 자리(오른쪽) BCD | GPIO5, 6, 7, 8 | 75, 77, 79, 81번 |
| (13) DP2 | 2번 자리 점 | GPIO9 | 83번 |
| (14) A | 엔코더 A상 (eQEP1 QEPA) | GPIO20 | 105번 |
| (14) B | 엔코더 B상 (eQEP1 QEPB) | GPIO21 | 107번 |
| (14) S/W | 노브 스위치 (누르면 High) | GPIO22 | 109번 |

![TMS320F28X EVM V2 — (13) 7-세그먼트와 (14) 엔코더를 A Side 핀-헤더에 연결한 결선](f28xevm_v2_encoder.png)

실선 10가닥이 (13) 7-세그먼트, 점선 3가닥이 (14) 엔코더입니다.

## 2. FreeRTOS 구성

| 태스크 | 우선순위 | 하는 일 |
|---|---|---|
| `Encoder_Task` | Idle + 2 | 10 ms마다 eQEP 위치와 노브 스위치를 읽어 `seg_counter`로 표시 값을 갱신. 출력 워드가 **바뀐 경우에만** 표시 태스크에 알림(`xTaskNotifyGive`) |
| `Display_Task` | Idle + 1 | `ulTaskNotifyTake`로 알림이 올 때까지 잠자다가, 깨어나면 7-세그먼트 GPIO를 갱신 |

- 스택은 태스크당 256워드, 전부 `xTaskCreateStatic`과 정적 버퍼를 씁니다(`configSUPPORT_DYNAMIC_ALLOCATION = 0`).
- 알림이 짧은 시간에 여러 번 와도 한 번에 모아서 처리하므로 항상 가장 최근 값이 표시됩니다.
- CCS Expressions 창의 `displayUpdateCount`는 표시 태스크가 7-세그먼트를 갱신한 횟수입니다. 노브를 돌릴 때만 올라가야 하고, 가만히 두면 멈춰 있어야 합니다.

## 3. 빌드

CCS에서 `CCS/13_14_SevenSeg_Encoder_Freertos.projectspec`을 Import하세요. FreeRTOS 커널과 driverlib을 프로젝트 폴더 안에 복사해 둔 자기완결형입니다.

## 4. 검증 상태

- **빌드로 확인함(2026-10-14)**: CPU1_RAM, CPU1_FLASH 구성이 모두 오류 없이 컴파일·링크됩니다. 공통 파일 `seg_counter.c`는 DriverLib 버전의 PC 테스트를 통과한 것과 같은 파일입니다.
- **보드에서 확인 전**: 엔코더 회전 방향, 눈금당 카운트, 노브 스위치 리셋, DP 점등, 7-세그먼트 자리 대응, 두 태스크의 알림 동작(`displayUpdateCount`).

## 5. 세 버전 메모리 사용량 비교

링커 맵의 영역별 사용량 합계(워드, 16비트)입니다. `--opt_level=off`, CGT 25.11.1.LTS로 측정했습니다.

| | 비트필드 | DriverLib | FreeRTOS |
|---|---|---|---|
| CPU1_RAM 구성 합계 | 4,739 | 5,721 | 9,585 |
| CPU1_FLASH 구성 — Flash | 4,929 | 5,166 | 8,001 |
| CPU1_FLASH 구성 — RAM | 307 | 1,267 | 2,296 |
| `FLASH_BANK0`(131,070워드) 대비 Flash | 약 3.8% | 약 3.9% | 약 6.1% |

RAM 차이의 대부분은 프로젝트의 스택/힙 설정에서 옵니다(비트필드 스택 0x100워드, DriverLib 스택 0x3F8 + 힙 0x200워드). 힙 영역은 쓰지 않아도 합계에 잡힙니다. 주변장치 레지스터 영역(EQEP1, GPIOCTRL 등)은 실제 메모리가 아니므로 합계에서 뺐습니다.
